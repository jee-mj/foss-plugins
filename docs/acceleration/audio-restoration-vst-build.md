# AudioRestorationVST source-plugin pilot — reviewed runtime revision

Date: 2026-10-17. AUDIO-013. Native Linux x86_64. Supplements the historical
assessment in `AUDIO-013.md`. No public exports/catalog/flake changes are made here.

## Decisions after independent review

1. **The plugin and JUCE remain source-built. ONNX Runtime is now an explicitly
   binary dependency**, using pinned official CPU/CUDA runtime-and-header archives.
   This is necessary to avoid acquiring the 856 `.onnx` test fixtures in the full
   nixpkgs ORT source. The earlier cached-runtime pilot did not acquire those
   fixtures, but its recipe could acquire them on a cold build. It did **not**
   establish a model-free cold-source guarantee and is superseded here.
   `runtime.nix` has no dependency on nixpkgs `onnxruntime` or ONNX source, and no
   source-build fallback. It records `binaryNativeCode` provenance. No release
   plugin binary is substituted for the source plugin.
2. **CUDA registration failure now throws and releases its `OrtStatus`.** The
   narrow production substitution wraps the upstream call in `Ort::ThrowOnError`.
   Its exception enters the existing catch, resets the session and returns false,
   before session creation or `activeProvider` assignment. The caller's existing
   provider-order logic permits CPU fallback only when configured. An unsuccessful
   CUDA registration can no longer create a CPU session labelled CUDA via this path.
3. **CPU transitive runtime closure isolation is tested**, using
   `exportReferencesGraph`, in addition to the plugin's direct DT_NEEDED checks.

## What the tests establish

The artifact check finds exactly one VST3 shared object, verifies ONNX DT_NEEDED,
loads it with `RTLD_NOW`, resolves `GetPluginFactory`, checks JUCE X11/OpenGL
dlopen libraries and rejects models/standalone executables. Its full runtime
closure contains no CUDA/cuDNN/ROCm/MIGraphX packages.

The provider check applies the real production `postPatch` to pinned upstream
source, extracts the real CUDA registration branch and fallback-order method, and
compiles a headless probe. CPU ORT lacks the legacy convenience symbol, so a
test-only ABI bridge delegates that signature to the **real ORT API-table CUDA
append operation**, without mocking its result. An ORT environment is created;
registration returns the real expected error, `Failed to load shared library`,
because the CPU runtime has no `libonnxruntime_providers_cuda.so`. No device/GPU
library is loaded. The error is caught as an exception. With fallback disabled,
the real order contains no CPU; with fallback enabled it reaches CPU. Source
contract assertions check registration rejection precedes session creation, which
precedes `activeProvider` assignment, and that the existing catch resets session.
The full patched denoiser also passes a CUDA-enabled syntax-only compile.

This probe checks failed registration and fallback **eligibility**, not successful
CPU fallback inference. It does not instantiate the full plugin/model session or
prove active-provider graph-node placement. Full-plugin inference/error behavior
requires an authorized model. Model execution, provider execution, GUI/DAW load,
state recall and latency remain **not-run**. AMD hardware stages remain
**not-run-policy**.
